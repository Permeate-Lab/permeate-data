# Permeate Lab public research mirror

Permeate Lab is a Nova3 AI research publication. This repository mirrors the public Northwest Florida engineering cost reference. Permeate Lab is the canonical publisher.

[Read the canonical reference](https://permeatelab.com/research/northwest-florida-engineering-costs/) · [Methodology](https://permeatelab.com/research/northwest-florida-engineering-costs/methodology.html) · [Current edition metadata](https://permeatelab.com/research/northwest-florida-engineering-costs/latest.json)

The `payload/` directory retains the publication's file names and relative paths, including the dated edition. It contains scoped planning references, public geographic context and reusable public data. The four price bands are indicative planning guidance; they are not representative market averages, provider offers or locally measured ZIP prices. Unknown expanded fees remain unpriced.

Edition: `permeate-nwfl-2026-10-01-r1`. The research cutoff and actual publication state are recorded inside the mirrored public files. This mirror is another distribution of the same publication, not independent corroboration.

## Parity verification

`verification-policy.json` (policy 2.1) defines how the mirror is checked against the live origin, and `mirror-manifest.json` is the current receipt produced under that policy. `scripts/verify_mirror.py` is the verifier; `scripts/test_wrapper_policy.py` holds its offline adversarial fixtures. Both use only the Python standard library.

- Non-HTML files (JSON, CSV, JavaScript, CSS, SVG, text) must match the live origin byte for byte.
- HTML files must equal the payload source exactly, or equal the source plus exactly one host block inserted immediately before the sole closing `head` tag. The hosting service inserts that block (an analytics script, `twitter:title`, `og:image` and `twitter:image`, plus `twitter:description` on pages whose source declares `og:description`). The block must match one of the two recorded block shapes byte for byte except the social-preview image filename, which must be identical in both image tags and must match the host, project prefix and `[0-9a-f]{32}_[0-9]{13}.png` pattern fixed in the policy. Extra tags or scripts, another host or project, unequal image URLs, a changed title, a `twitter:description` that differs from the source `og:description`, a moved or duplicated block, or any edit to the source bytes fail verification.
- The social-preview image filename is regenerated by the host and may change without a content change. The verifier reports the change and the regenerated manifest records the new URL. This policy does not validate the image's visual contents and does not claim raw HTML byte equality. Preview responses are not used.

The manifest records, per file, the payload SHA-256, the live raw SHA-256, the parity mode, the observed host block and its image URL, and the response headers (`x-deployment-id`, `content-type`, `cache-control`) captured at the observation time stated in `verified_at`.

```
python3 scripts/test_wrapper_policy.py                     # offline policy fixtures
python3 scripts/verify_mirror.py --verify                  # check payload and manifest against live origin
python3 scripts/verify_mirror.py --regenerate --previous receipts/<old manifest>.json
```

Superseded manifests are kept under `receipts/` as historical evidence of the delivery observed at their recorded time. `receipts/mirror-manifest-2026-10-01T19-02-26Z.json` is the policy 1.0 receipt taken before the host regenerated the social-preview image on October 1, 2026; it is retained, not corrected. `receipts/mirror-manifest-2026-10-01T20-32-15Z.json` is the policy 2.0 receipt taken before the October 1, 2026 publication that added structured data, distinct descriptions, footer links and icon links to the ten current edition pages; the host began adding `twitter:description` to those pages at that publication, which policy 2.1 bounds.
